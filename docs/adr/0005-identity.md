# ADR-0005: Identity: node IDs, keys, labels, and weights

- **Status:** Accepted (2026-10-27)
- **Date:** 2026-10-27
- **Related:** ADR-0002, ADR-0006; tickets FR-004, FR-007

## Context

Placement depends on a node's *identity*. If the bytes behind that identity change, the ring sees a different node and the node's data moves. Addresses do change: DHCP leases expire, laptops move between networks, and containers get rescheduled.

Keys are database names, and they will come from many languages and clients. If one client silently normalizes a name (Unicode NFC, case folding, trimming) and another doesn't, the two will place it differently.

## Decision

1. **A `NodeId` is stable and is never an address.** It's assigned once, by an operator or generated by `fleetringd` on first boot and persisted, and it lasts for the node's lifetime. Addresses and endpoints live in `fleetringd`'s membership table, not in the ring. To the ring, renaming a node is a removal plus an addition.
2. **Labels follow a strict grammar for now.** `NodeId`, `Zone`, and `Host` are validated newtypes: 1–64 bytes drawn from lowercase ASCII letters, digits, `-`, `_`, `.`, and `:`. UUIDs, hostnames, and names like `region:zone` all fit. They're constructed through `FromStr` or `TryFrom<&str>`, never an infallible `From`. Relaxing the grammar later won't break anyone; tightening it would.
3. **Keys are opaque bytes.** Lookups take `impl AsRef<[u8]>`, so `&str`, `String`, and byte slices all work, and the bytes are hashed exactly as given. The library imposes no grammar and no length limit. The router and daemon own naming rules: allowed characters, maximum length, canonical case.
4. **A weight is relative capacity.** `Weight` wraps a nonzero `u32` and defaults to 1. Rendezvous uses only ratios between weights; the vnode ring multiplies each weight by `tokens_per_weight`. Zero isn't a valid weight. To drain a node, build a target ring without it (ADR-0001).
5. **Node order is canonical.** A ring depends only on its *set* of nodes. Nodes are sorted by `NodeId` bytes at build time, so the order they were added in never matters. A duplicate ID is a build error.
6. **Each node is hashed once.** `node_hash = H(id_bytes, seed)` is computed at build time and reused for every draw and every token.

## Alternatives considered

- **Numeric node IDs (`u64`):** compact, but unreadable in CLI output and logs, and they'd still need an external map between names and IDs.
- **A generic `N: AsRef<[u8]>` node type:** more flexible, but every API would carry another type parameter, and the spec couldn't say what a node ID is.
- **Normalizing keys inside the library:** this would hide a cross-language trap, not remove it, since Unicode normalization tables change between versions.

## Consequences

- Operators see placement output they can read: `agent:sam → [laptop-2, nas, laptop-1]`.
- A node's identity matters for placement, so the docs and the daemon must make renaming an explicit operation that moves data.
