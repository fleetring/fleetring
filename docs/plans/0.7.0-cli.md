# 0.7.0: the CLI experience

ADR-0043 (Proposed) is the design, and [`docs/cli.md`](../cli.md) the style guide this plan builds to. Read both first. Each phase restates only what its implementer needs; where it says "as ADR-0043 point N", the ADR's text is the specification.

From #103:

## Phases, dependencies and parallelism

```text
A1 ─▶ A2 ─┬──▶ B contexts ──┬──▶ C detach/stop ──▶ F agents ──┐
           │                 └──────────────────────▶ G1 json ──┤
           ├──▶ D1 spinners ────────────────────────────────────┤
           └──▶ E archive group, node list ─────────────────────┴──▶ D2 help ──▶ G2 completions, man pages
```

- **A is two pull requests, and they land first, in order.**
  - **A1, the upgrade and compatibility change:** the name handling, the implied `serve`, the archive with both entries, the kept process-file, lock and variable names, `check-archive.sh`, the packaging that the build's new file name breaks (the release and container workflows, the `Dockerfile`, `install.sh`), and the nightly test. It renames the binary, so it also touches every test (`CARGO_BIN_EXE_fleetringd` becomes `CARGO_BIN_EXE_fleetring`). It stays small enough to review for the upgrade path alone.
  - **A2, the sweep:** docs, `deploy/`, the site, `RELEASING.md` with its release-notes draft, and the lexicon. It changes no Rust outside `tests/deploy.rs` and `tests/agents_skill.rs`.
- **B, D1 and E run in parallel** once A1 has merged, in their own worktrees, and rebase onto A2, which changes only docs.
- **C starts with B, but merges after it.** C's summary lines print the `dev` context, which B's `fleetring_client::context` API provides. Every signature that C uses is fixed in phase B below, so C codes against it and rebases.
- **F needs B and C,** because it acquires a node through C's detach and selects a context through B.
- **G1** (the rest of FR-056: JSON, exit codes, hints, confirmation, quiet and colour, and moving the client into `fleetring-client`) needs B, which creates the crate. It touches every command, so it merges after C, E and F to keep their rebases small.
- **D2 rewrites every help comment** and adds the grouped layout, so it goes after every phase that adds a command: B, C, E, F and G1.
- **G2 (completions and man pages) is last,** because it renders the final tree.
- **Pushes.** Parallel phases run every gate locally and don't push. The lead orders the pushes so that each pull request costs one CI run.
- **Reviews.** Phase A1 (the upgrade path) and phase F (minting credentials) each get an independent review before they merge.

**Conventions for every phase.** Paths are under `crates/fleetringd/` unless they say otherwise.

- **Code rules:**
  - Load `beautiful-rust:rust-best-practices`.
  - New public types derive `Debug` and join their crate's `Send + Sync` assertion list in `lib.rs`.
  - Errors are `#[non_exhaustive]` `thiserror` enums with lowercase messages.
  - No `bool` parameters: use two-variant enums.
  - No `HashMap` or `HashSet`; no `unwrap()` outside tests; `#[expect(…, reason = "…")]`, never a bare `allow`.
  - `unsafe` is forbidden: no `pre_exec`.
- **Every word comes from `docs/lexicon.md`.** A phase that needs a new one adds it there in the same pull request.
- **Commits:** Conventional Commits with `Refs: #103`, `Refs: #59` or `Refs: #114`. No AI attribution, and never `--no-verify`.
- **Gates:**
  - `cargo fmt --all`
  - `cargo clippy --workspace --all-targets --all-features -- -D warnings`
  - `cargo test --workspace --all-features`
  - `RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --all-features`
  - `cargo +1.88 check --workspace --exclude fleetringd --exclude fleetring-client --all-features --all-targets` (from phase B on; before it, without the second `--exclude`)
  - `cargo +1.89 check -p fleetringd -p fleetring-client --all-features --all-targets` (from phase B on)
  - `cargo deny check` (phases B, D1 and G2, which add dependencies)

### A.2 New bin module `src/compat.rs` (`mod compat;` in `main.rs`)

```rust
/// The name the binary was run as, which it prints in `--version`, usage and errors (ADR-0043
/// point 1.3). Nothing else depends on it.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub(crate) enum ProgramName { Fleetring, Fleetringd }

impl ProgramName {
    /// `Fleetringd` if `arg0`'s file name starts with `fleetringd` (`fleetringd`,
    /// `fleetringd.exe`, `fleetringd.previous`); `Fleetring` otherwise, and for `None`.
    pub(crate) fn from_arg0(arg0: Option<&std::ffi::OsStr>) -> Self;
    pub(crate) fn as_str(self) -> &'static str; // "fleetring" | "fleetringd"
}

/// 0.6's top-level daemon flags, which mean `serve` until 1.0 (ADR-0043 point 1.4).
pub(crate) const LEGACY_DAEMON_FLAGS: [&str; 8] = [
    "--config", "--node-id", "--data-dir", "--listen", "--advertise", "--control", "--role",
    "--insecure-plaintext",
];

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub(crate) enum Invocation { AsWritten, ServeImplied }

/// Inserts `serve` before the first argument if, after any leading `--log-format <v>` or
/// `--log-format=<v>`, that argument is one of [`LEGACY_DAEMON_FLAGS`] alone or as `--flag=value`.
/// `args[0]` is the program and is never touched.
pub(crate) fn imply_serve(args: Vec<std::ffi::OsString>) -> (Vec<std::ffi::OsString>, Invocation);
```

Unit tests in `compat.rs`:

- `from_arg0`, over `/usr/bin/fleetringd`, `fleetringd.exe`, `fleetringd.previous`, `fleetring`, `fleetring.exe`, `/x/fleetring.previous` and `None`.
- `imply_serve`, over:
  - `[p, --config, f]` and `[p, --config=f]`, which get `serve`;
  - `[p, --log-format, json, --config, f]`, which gets `serve` after the format;
  - `[p, --insecure-plaintext, --config, f]`, which gets `serve`;
  - `[p, db, list]`, `[p]`, `[p, --help]`, `[p, -V]` and `[p, serve, --config, f]`, which stay as written;
  - `[p, --context, x, db, list]`, which stays as written (`--context` isn't a daemon flag).

### A.3 `src/main.rs`

1. **The command is named `fleetring`.** Add `name = "fleetring"` to `#[command(…)]` on `Cli`. Remove `daemon: DaemonArgs` from `Cli`, `subcommand_negates_reqs`, and `Cli::check`, whose conflict no longer exists. `command` becomes required, and clap prints help and exits 2 when it's missing (`arg_required_else_help = true`).
2. **Add `Serve(DaemonArgs)`** to `Command`, first in the enum. `DaemonArgs::config` becomes `#[arg(long)] config: PathBuf`, which is required. Its doc comment is one line: `Runs a node`. The details go below a blank line (phase D2 polishes them), and the compatibility form is stated in its `long_about`.
3. **`main()`** parses in this order:

   ```rust
   let raw: Vec<OsString> = std::env::args_os().collect();
   let name = compat::ProgramName::from_arg0(raw.first().map(OsString::as_os_str));
   PROGRAM.set(name).ok(); // static PROGRAM: OnceLock<ProgramName>
   let (args, invocation) = compat::imply_serve(raw);
   // Both: display_name sets --version; usage lines come from bin_name, which clap would
   // otherwise take from argv[0] verbatim (`fleetringd.previous`, `.fleetringd.new`).
   let matches = Cli::command()
       .display_name(name.as_str())
       .bin_name(name.as_str())
       .try_get_matches_from(args);
   let cli = matches.and_then(|m| Cli::from_arg_matches(&m)); // then today's error handling
   ```

   `Run::Daemon` is built from `Command::Serve(args)`, loading `args.config`, and from `Command::Dev(args)` as today. With `Invocation::ServeImplied`, once logging is up, log one warning:

   ```text
   starting without `serve` is kept until 1.0; run `fleetring serve --config <file>`
   ```

4. **Error prefixes use the name it ran as.** `report()` and every `eprintln!("fleetringd: …")` use `program()`, which returns `PROGRAM.get().copied().unwrap_or(ProgramName::Fleetring).as_str()`. Every user-facing string that names the binary in `main.rs`, `edit.rs` and `upgrade/` says `fleetring`, apart from the compatibility text. That includes `MCP_HELP` (`"command": "fleetring"`) and the hints.
5. **A restart in place keeps the name it was started with.** In `restart_in_place`, add `.arg0(std::env::args_os().next().unwrap_or_else(|| exe.as_os_str().to_owned()))`.
6. **`parse_release`** keeps accepting the `fleetringd-v` prefix: the tags keep it.

### A.4 `upgrade/` (ADR-0043 point 3)

- **`install.rs`:**
  - `extract(archive, release, target, into)` looks for `fleetringd-{release}-{target}/fleetring` and `…/fleetringd` in one pass. It prefers `fleetring` and falls back to `fleetringd` (a release before 0.7). Both must be regular files. The error names both paths when neither is there. Update its doc comment.
  - `version_of` accepts stdout `fleetring <v>` or `fleetringd <v>`. Its error text says `'fleetring <version>'`.
  - `Installed::sibling`'s fallback name becomes `"fleetring"`.
  - New: `pub(crate) fn complete_names(&self) -> Result<Option<PathBuf>, UpgradeError>`. On Unix, if the installed file's name is `fleetringd` and `symlink_metadata(dir/"fleetring")` is `NotFound`, it creates the relative symbolic link `fleetring -> fleetringd` and returns its path. Otherwise, and on Windows, it returns `Ok(None)`.
- **`mod.rs`:**
  - `fetch` names the scratch binary `fleetring`.
  - `install` and `roll_back` call `installed.complete_names()` after a successful swap, and add `added fleetring beside fleetringd at <path>` to the report.
  - The messages say `fleetring`.
  - New refusal `UpgradeError::StartedWithServe { release: Release }`:

    ```text
    fleetring {release} doesn't know `serve`, which this node was started with
      hint: start the node with `fleetringd --config <file>` instead, restart it, then roll back again
    ```

    `install` (for `--version` older than 0.7.0) and `roll_back` (when the previous binary reports a release older than 0.7.0) apply it before swapping anything, with or without `--no-restart`, and whether this 0.7 binary is the installed one or the kept `.previous` one:
    - **With a running daemon** (`running_daemon` found its process file), refuse when its `args` start with `serve`, after any `--log-format` and its value.
    - **Without one,** the arguments can't be seen. On a terminal, ask `does any node on this machine start with 'fleetring serve'? 0.6 can't run it [y/N]`, and refuse on yes. Without a terminal, refuse with `UpgradeError::StartCommandUnknown { release }` unless `--yes` is given; `upgrade` gains `--yes` for this. Never only warn.

    The 0.6 binary kept as `fleetringd.previous` can't apply any of this when it runs `upgrade --rollback` itself (ADR-0043 point 3.5), so the release notes carry the unit-first rule (A.7, `RELEASING.md`).
- **`process.rs`:**
  - `ProcessFile` gains `#[serde(default)] pub args: Vec<String>`, filled by `this_process` from `std::env::args_os().skip(1)`, lossily. A 0.6 reader ignores the field.
  - Add a doc comment on `PROCESS_FILE`, `LOCK_FILE` and `RESTARTS_VAR`: their names are kept until 1.0, because a 0.6 upgrader and a 0.6 daemon use them.
  - Add the test `the_names_a_0_6_upgrader_uses_are_kept`, which asserts the three string values.

Unit tests:

- `extract_prefers_fleetring_and_falls_back_to_fleetringd`: build three `.tar.gz` files in a temporary directory, one with both entries, one with only `fleetringd`, and one with `fleetringd` as a symbolic link only, which is refused.
- `version_of_accepts_both_names`: two shell scripts that print each form.
- `complete_names_links_fleetring_beside_a_fleetringd_file`.
- `complete_names_leaves_an_existing_fleetring_alone`.
- `a_rollback_past_the_rename_is_refused_for_a_node_started_with_serve`: a process file with `args = ["serve", "--config", "x"]`, the previous binary a script printing `fleetringd 0.6.0`, and `UpgradeError::StartedWithServe` before any swap, with and without `--no-restart`.
- `a_downgrade_past_the_rename_without_a_node_needs_yes`: `--version 0.6.0` with no `--config` and no terminal refuses with `StartCommandUnknown`, and swaps with `--yes`.

`src/dirs.rs`:

```rust
/// The configuration directory: `$XDG_CONFIG_HOME/fleetring` if that is set and absolute, else
/// `$HOME/.config/fleetring`, on Linux and macOS; `%APPDATA%\fleetring` on Windows.
pub fn config_dir(env: &dyn Fn(&str) -> Option<std::ffi::OsString>) -> Result<PathBuf, DirsError>;
/// The data directory for files a program wrote: `$XDG_DATA_HOME/fleetring` if set and absolute,
/// else `$HOME/.local/share/fleetring`; `%LOCALAPPDATA%\fleetring` on Windows. Phase F uses it.
```

### F.1 New bin module `src/agent.rs`

```rust
/// An agent's ID: 1-32 of `[a-z0-9_]`. Its principal is `agent-<id>` (ADR-0043 point 8.5).
#[derive(Debug, Clone, PartialEq, Eq, PartialOrd, Ord)]
pub(crate) struct AgentId(String);
impl FromStr for AgentId { type Err = AgentError; }
impl AgentId {
    pub(crate) fn principal(&self) -> Principal;           // agent-<id>
    pub(crate) fn default_scope(&self, access: Access) -> Scope; // admin:agent-<id>-* or read:agent-<id>-*
}

/// `identity.toml`: no secret.
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
#[serde(deny_unknown_fields)]
pub(crate) struct AgentRecord { pub(crate) version: u32, pub(crate) principal: String, pub(crate) owner: String, #[serde(default, skip_serializing_if = "Option::is_none")] pub(crate) parent: Option<String>, pub(crate) fleet: String, pub(crate) scopes: Vec<String>, pub(crate) read_only: bool, pub(crate) token_id: String, pub(crate) token_expires_at: String, pub(crate) cert_expires_at: String, pub(crate) issued_by: IssuedBy }
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)] #[serde(rename_all = "lowercase")]
pub(crate) enum IssuedBy { Dev, Authority }   // `Enrollment` arrives with its ADR

/// One agent's directory (ADR-0043 point 8.3).
#[derive(Debug, Clone)]
pub(crate) struct AgentDir { dir: PathBuf, id: AgentId }
impl AgentDir {
    pub(crate) fn new(agents_dir: &Path, id: AgentId) -> Self;
    pub(crate) fn tls_dir(&self) -> &Path;   // the directory itself
    pub(crate) fn token_file(&self) -> PathBuf;
    pub(crate) fn record(&self) -> Result<Option<AgentRecord>, AgentError>;
    /// Mints a certificate and a token from `authority` and writes them, with `ca.crt` and
    /// `identity.toml`: files `0600` and the directory `0700`, each written to a temporary name and
    /// renamed. Holds `<dir>/.lock` while it works.
    pub(crate) fn mint(&self, authority: &Authority, grant: MintGrant, now: Timestamp) -> Result<AgentRecord, AgentError>;
    /// What a start needs to do: nothing, renew the certificate, renew the token, or both
    /// (ADR-0043 point 8.2).
    pub(crate) fn renewal(&self, record: &AgentRecord, ca_pem: &str, now: Timestamp) -> Renewal;
    pub(crate) fn remove(&self) -> Result<(), AgentError>;
}
pub(crate) struct MintGrant { pub(crate) scopes: Vec<Scope>, pub(crate) access: Access, pub(crate) cert_ttl: Duration, pub(crate) token_ttl: Duration, pub(crate) issued_by: IssuedBy }
#[derive(Debug, Clone, Copy, PartialEq, Eq)] pub(crate) enum Renewal { None, Certificate, Token, Both }
#[derive(Debug, Clone, Copy, PartialEq, Eq)] pub(crate) enum Access { ReadWrite, ReadOnly }

/// Where `--agent` identities live for the selected context (ADR-0043 point 8.4).
pub(crate) fn agents_dir(context: Option<(&ContextName, &Context)>, env: &dyn Fn(&str) -> Option<OsString>) -> Result<PathBuf, AgentError>;
```

- **Minting** uses `Authority::load(dir)?`, `authority.issue_client(&principal, validity)`, and `authority.token_signer()?.issue(&Grant { … })`, the same calls `cert client` and `token issue` make. Factor the token-ID generation out of `TokenCommand::Issue` into `fn new_token_id() -> Result<TokenId, …>`.
- **Lifetimes:** in dev mode the certificate lasts 365 days and the token 30 days. With `--authority`, the certificate lasts `--ttl` (30 days by default) and the token `min(--ttl, 30 days)`.
- **The scope separator:** call `Scope::separator_warning` on every `--scope`, and print the warnings as `token issue` does.
- **Lineage:** `owner` is the principal the command resolved (`admin` in dev mode), or `"authority"` for `--authority` without one; `parent` is always `None` in 0.7.
- **Reserved scope words (ADR-0043 point 8.11):** in `src/auth/scope.rs`, `Scope::from_str` refuses `fork`, `grant`, `fork:<pattern>` and `grant:<pattern>` with a new `ParseScopeError::Reserved { word }` (`'{word}' is reserved for delegation, which this release doesn't support`). Token verification refuses a token carrying one, since it parses scopes the same way. Tests: `reserved_scope_words_are_refused` (unit), and `token_issue_refuses_fork_and_grant` (integration).

### F.3 `mcp --agent`

**`McpArgs`** gains nothing new: `--agent` comes with `Target`. In `Command::Mcp`, before `target.client()`, call:

```rust
/// ADR-0043 point 8.1: in dev mode, acquire a node and an identity, then return; elsewhere,
/// check the identity exists.
async fn prepare_agent(target: &Target, env: &EnvSnapshot, store: &ContextStore) -> Result<AgentReady, AgentError>;
```

It runs these steps:

1. **Decide whether to try dev mode:** the selected context has `dev_dir`, or there is no selected context and none of the connection flags or variables are set. This only says where to look; it authorizes nothing.
2. **In dev mode, acquire a node:** `dev_dir = context.dev_dir.unwrap_or(dev::default_dir()?)`. Under `<dev_dir>/fleetring.start.lock`, if `process::running(<dev_dir>/data)` isn't `Yes`, run `dev::prepare` and then `dev::detach` with the 60s timeout, and write the `dev` context (`upsert_dev`).
3. **Check the directory, then load the identity.** Immediately before any mint or renewal, and whether or not step 2 found a node already running (so `prepare` never ran), call the new read-only `dev::check_dev_dir(dev_dir: &Path) -> Result<DevChecked, DevError>`. It runs ADR-0039 point 3's checks without creating anything: `fleetringd.toml` exists, says `dev = true`, and passes `Config::validate` (every address on loopback); `tls/` holds only dev mode's files; and `ca.crt` names the fleet `dev`. Its failure stops the command, with nothing minted. `AgentDir::mint` takes the `DevChecked` value, or an explicit `--authority` for `IssuedBy::Authority`, and only `check_dev_dir` can construct `DevChecked`, so no path reaches a dev mint without it. `agent add` and `agent renew` in dev mode call it too. Then use `AgentDir::new(<dev_dir>/agents, id)`: mint one if there is no record, otherwise apply `renewal`. On renewal, revoke the old token with `Control.RevokeToken` through the dev context's admin identity, logging a warning on failure.
4. **Serve:** set `read_only` from the record, unless `--read-only` was given, and serve.

Everything goes to stderr, and `Progress` is constructed with `machine_output = Yes`, because stdout is the protocol. Before serving, it prints one line: `serving MCP as agent-42 on context 'dev'; certificate expires <date>, token expires <date> (renewed at start when under 7 days)`.

## Open questions for the owner

Decided on 2026-11-06: the owner took every recommendation below, and the reviewer's precedence fix (ADR-0043 point 4.4).

1. **`db watch` is deferred to its own ticket and ADR,** so that 0.7.0 changes no protocol. Recommended: defer.
2. **Should `--agent` work on every client command?** Recommended: yes, using an identity that exists, so a person can see what the agent sees (`fleetring db list --agent 42`). Only `mcp --agent` and `agent add` mint.
3. **Where agent identities live.** Recommended: beside the dev authority (`~/.fleetring/agents/<id>/`) for the dev context, and `$XDG_DATA_HOME/fleetring/agents/<context>/` for others, never as contexts.
4. **The release tag and archive names** (`fleetringd-v…`, `fleetringd-<v>-<target>`). Recommended: keep them through 0.x, since a 0.6 upgrader needs them, and decide at 1.0 with `fleetring-cli`.
5. **Windows `dev -d` and `stop`.** Recommended: refuse in 0.7, with a clear message, and ticket it.
6. **`fleetring stop` with no flag.** Recommended: a usage error with the `dev stop` hint, rather than defaulting to the dev node.
7. **Renewing an agent's token inside a running MCP server.** Recommended: not in 0.7; renew at start when fewer than 7 days remain, and say "restart the MCP server" on expiry.
8. **`agent add --authority` for non-dev fleets.** Recommended: yes, explicit only, until enrollment's ADR.
